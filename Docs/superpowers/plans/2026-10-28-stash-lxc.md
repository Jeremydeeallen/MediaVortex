# Stash LXC Implementation Plan

> **Status 2026-10-29:** Tasks 1-6 done (infra commits up to `0eec064`). Task 7 is Phase 1 of `2026-10-29-xxx-program.md`; its live state is in the memory handoff. SSoT for the domain is infra `docs/architecture/xxx-curation.md`; criteria and evidence are in infra `docs/features/stash-deploy.feature.md`. This plan is history, not a contract.

**Goal:** Stand up a Stash instance (CT `stash`, VMID 233, 10.0.0.45) on Porky with the xxx video dataset bind-mounted read-only, reachable at `http://stash/`, scraping ThePornDB (StashDB optional, invite-gated), so the operator can rate performers.

**Architecture:** Follows the infrastructure repo's server-deploy pipeline exactly: one `services` row in infra-db -> regenerate `terraform/inventory.toml` -> `server-deploy.py --name stash` (validate, scaffold `lxc-bind-mount`, terraform apply, DNS, monitoring, nginx, backup, docs) -> `app-deploy.py --name stash` (systemd app: binary from GitHub release URL + unit file). Stash data (sqlite, generated, blobs) lives on the CT root disk on `local-zfs`; media is a read-only bind mount of Porky's local ZFS dataset, so there is no NFS hop.

**Tech Stack:** Proxmox LXC (Ubuntu 24.04 template on Porky), Terraform bpg/proxmox via the repo scaffold, infra-db Postgres (psycopg2), Stash v0.31.1 `stash-linux` binary, ffmpeg from apt, systemd.

**Deviations from the spec (`Docs/superpowers/specs/2026-10-28-xxx-stash-cull-audio-design.md` Unit 1):**
- Host is **Porky** (10.0.0.43), not Larry. The xxx dataset is `tank/media/xxx_videos` on Porky; Larry only has it over backplane NFS.
- Template is **Ubuntu 24.04** (the only LXC template on Porky and the repo default), not Debian 12.
- Everything else (unprivileged, read-only media mount, native binary + systemd, port 9999, ThePornDB; StashDB only with an invite) stands.

**Working directories:** infrastructure repo at `C:\Code\infrastructure` (all file edits + commits there). MediaVortex repo only holds this plan and the spec.

## Consumers

| Consumer | Reads | Writes |
|---|---|---|
| Operator (browser) | Stash UI via nginx `http://stash/` | performer ratings, tags, scraper keys |
| Stash | `/mnt/xxx` (ro), StashDB, ThePornDB | its own sqlite + generated files |
| MediaVortex `xxx-cull` | Stash GraphQL | nothing in Stash |
| vzdump (Porky nightly) | CT root disk | backup archive |

## Invariants (Enforceable)

1. The media bind mount is read-only (`ro=1` in the CT config). `touch /mnt/xxx/Videos/x` inside the CT fails.
2. Stash never deletes media. Deletion happens only in MediaVortex after operator confirmation.
3. Stash's own data lives on the CT root disk, which vzdump backs up. The media mount is `backup=0`.
4. The CT is unprivileged.

## Tradeoffs (Locked)

- **Stash over a MediaVortex-native performer UI**: the rating UI with photos is the expensive part; Stash has it. MediaVortex owns only the delete.
- **Porky over Larry**: the dataset is Porky-local ZFS. No NFS hop, no backplane dependency.
- **Native binary over Docker**: one Go binary, no compose file, unprivileged CT with no nesting tricks.
- **No face recognition**: identity comes from scrapers by hash and filename.

## Deferred

- Preview/sprite generation for all scenes (disk cost on `local-zfs`). Trigger: operator wants hover previews.
- Exposing Stash outside the LAN. Trigger: none planned.

## Common Mistakes

- Mounting the media read-write "to let Stash organise files". Refused by invariant 1.
- Pointing Stash at the NFS export from another host instead of the local dataset.
- Storing scraper API keys in `config.yml` committed to a repo.

            m = re.search(r"/download/([^/]+)/", package)
